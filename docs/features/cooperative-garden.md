# 社区合种瓜田

个人签到与合种互相独立。原有个人瓜田仍累计七天收获；合种不会修改个人签到、连续天数或个人西瓜数量。

## 一起种的规则

- 大厅 `/garden/coops` 和详情 `/garden/coops/:id` 向游客开放，兼容 `/melon` 前缀。正常登录账号可创建、加入和浇水。
- 每块最多 10 人，每个账号最多同时参与 3 块。创建即加入，占用一个名额；公开加入不需要审批。
- 每个账号在北京时间每天最多成功浇水一次，选择一块瓜田贡献 1 点成长。换队、重复点击和重试不恢复资格；失败请求不消耗资格。
- 累计 35 次浇水成熟。0 点等待播种，1–34 点按比例展示播种至长大，35 点才成熟。成熟当天暂停浇水，次日首次有效浇水开启下一轮。
- 漏签不枯萎，退出不撤回成长。本轮所有实际贡献者去重获得合种纪念，包括成熟前退出的人；纪念获得者可能多于成熟时的在队人数。
- 公共西瓜篮每轮只增加一颗；个人合种纪念另行收藏，不兑换、不计入个人西瓜，也不用于牌室。
- 负责人可编辑 2–24 字名称和最多 160 字简介，不踢人。退出或账号失去参与权限时，交接给当前最早加入的正常成员；加入时间相同时按成员记录 ID 稳定排序。空田保留进度，下一位正常加入者接管。
- 重新加入按新的加入时间排序，不自动拿回管理权。封禁或限制中的成员保留关系和贡献，但不能写入；解封不抢回已交接的管理权。

## 页面与操作

个人页与合种页使用两个导航入口。首页保留原来的个人签到按钮，并补充合种链接。大厅显示我的最多三块瓜田、公开搜索和每页 20 条列表，按最近浇水时间、创建时间及 ID 排序。

详情展示共享瓜苗、成员与贡献、最近 20 次动态、分页公共收获，以及仅本人可见的分页合种纪念。手机先显示成长与操作，插画放在操作之后。分享通过复制详情 URL 完成，剪贴板不可用时显示手动复制链接。

退出采用页面内二次确认，可以取消。创建或编辑失败保留输入；创建请求标识在重试时保持一致，避免重复创建。可见页面每 15 秒刷新，回到页面和跨北京时间零点时也会更新。账户切换清空上个账号的界面状态，写入期间暂停轮询，避免旧响应覆盖新结果。

## 接口

| 路径 | 用途 |
| --- | --- |
| `GET /api/garden/coops?q=&page=1` | 公开搜索与分页，附服务器时间和下次重置时间 |
| `POST /api/garden/coops` | `{name, intro, requestId}` 创建并加入；`requestId` 为重试时保留的客户端 UUID |
| `GET /api/garden/coops/me?page=1` | 本人参与状态、今日浇水位置及分页纪念，不接受指定其他账号 |
| `GET /api/garden/coops/:id?page=1` | 公开详情、成员昵称与贡献、动态及分页公共收获 |
| `PATCH /api/garden/coops/:id` | 当前负责人提交 `{name, intro}` |
| `POST /api/garden/coops/:id/join`、`leave`、`water` | 仅接受 `{}`；重复加入和同田同日浇水幂等 |

创建返回 201，重试读取已创建瓜田返回 200。游客写入为 401；越权、非成员浇水或异源写入为 403；容量、参与数量、每日资格及当天成熟冲突为 409；非法输入为 400，不存在路径为 404。

个人状态要求正常账号。公共接口不展示邮箱、IP、密码、封禁原因或个人签到，全部响应保持 `Cache-Control: no-store`。原 `/api/garden` 和 `/api/garden/check-in` 契约不变。

## 数据与事务

迁移 `0006_cooperative_garden` 新增瓜田、历史成员关系、轮次、浇水和纪念五张表，不修改旧签到数据。创建、首轮和自动加入通过 `DB.batch` 一起完成。容量与参与数量由触发器检查，有效成员有部分唯一索引。

每日资格由 `(user_id, day)` 唯一约束和条件插入保证。单次浇水语句的触发器完成新轮初始化、成长和成熟纪念发放；纪念有“瓜田＋轮次＋账号”唯一约束。账号检查和管理权交接同样在数据库执行，不能改成仅依赖客户端判断或进程内锁。

SQLite 与 D1 共用语句。当前 Wrangler 4.92 的 SQL 分割器需要 `CASE` 前和 `END` 后留空白，迁移与共享 SQL 保留对应写法，本地 D1 测试覆盖此兼容性。D1 批处理语义见 [官方绑定文档](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)。

## 本地演示与检查

演示须显式执行，不随应用启动。命令仅允许回环来源、非生产环境和名称含 `cooperative-garden-qa` 的独立目录：

```sh
export MELON_DATA_DIR="$PWD/.sites-runtime/cooperative-garden-qa-email-qa"
export MELON_PUBLIC_ORIGIN=http://127.0.0.1:5212
export NEXT_PUBLIC_BASE_PATH=/melon
node scripts/init-ecs.mjs
npm run garden:seed-cooperative
```

包含三块明确标识为虚构的瓜田，覆盖空田、34 点即将成熟、当天成熟和长标题。重复执行重置这三块演示瓜田，不插入个人签到。本地虚构账号为 `coop_demo_0` 到 `coop_demo_9`，统一密码 `Local_Garden_Demo_2026`，不发送真实邮件。

按 [开发指南](../development.md#邮箱验证隔离测试) 启动 Node 开发服务，将端口与目录替换为上述值。构建后生产预览不支持模拟注册，但可登录本地演示账号。

```sh
npm run test:cooperative
# Worker 构建后，仅在新建的本地 D1 模拟目录运行：
npm run test:cooperative-d1
# Node 隔离服务启动后：
MELON_TEST_URL=http://127.0.0.1:5212/melon npm run test:cooperative-api
# 实际重启相同服务后：
MELON_TEST_URL=http://127.0.0.1:5212/melon npm run test:cooperative-api -- --after-restart
```

HTTP 测试第一阶段保留私密检查点，第二阶段只清理本轮测试账号和瓜田；不能对生产库运行。实际结果见 [合种验证记录](../verification/cooperative-garden.md)。

## 交付与回退

本轮仅本地分支预览，不推送、不部署。将来发布应先备份、避开进行中的牌局，再应用新增迁移。应用回退保留新增表和用户内容，不导回旧库。成员及纪念引用账号，后续账号删除工具也必须显式处理这些关系。
