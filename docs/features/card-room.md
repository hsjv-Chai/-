# 🍉 牌室

入口 `/games`，ECS 入口 `/melon/games`。复用社区账号，登录后可创建斗地主或掼蛋房间，将页面上的邀请链接发给朋友。等待中的房间也会出现在大厅。点击空座可以选择位置；掼蛋一、三号座为一队，二、四号座为另一队。全员准备后自动开始。

## 玩法

- **斗地主**：3 人，54 张牌，17 张手牌与 3 张底牌。随机首叫，依次叫 1–3 分，不叫记 0；3 分立即确定地主，否则最高分为地主，全不叫则首叫者以 1 分当地主。地主先出，任一方出完获胜。支持单张、对子、三张、三带一/二、顺子、连对、飞机及带单/对、四带二/两对、炸弹、王炸。飞机单翅允许对子，不允许三张、炸弹或双王；四带二可带一对。
- **掼蛋**：4 人、108 张牌、每人 27 张，对家搭档。双副牌的同花同点两张牌各有独立编号。双方从 2 开始；头二升 3、头三升 2、头末升 1，最高到 A。必须实际打本方 A 且取得头二/头三才赢得整场；未过 A 保留级别，本牌室不采用“三次不过 A 掉级”。获胜方的级别决定下一副级牌。
- **掼蛋牌型**：红心级牌可配非王牌，两张红心级牌单独出只能作级牌对子。单张、对子、三张、三带二、五张顺子、三连对、两组三张钢板、四至十张炸弹、同花顺和四王。A 可作最小点数；顺子类按自然点数，不按级牌提升。四王 ＞ 六张以上炸弹 ＞ 同花顺 ＞ 五炸 ＞ 四炸。百搭有多种解释时，可在出牌前选择声明。单张级牌仅次于大小王。
- **升级与接风**：头二同队可提前结束本副，否则记录到第三位出完。领出者出完后，若其他仍有牌的玩家都过，其队友接风领出。
- **进贡、还贡、抗贡**：单贡由上副末游向头游；双下时两个输家分别贡牌，大贡给头游，同点贡随机对应。进贡除红心级牌外的最大牌；还贡选 ≤10 的非级牌，没有则还最小牌。按实际收贡对象还牌。单贡方持两个大王或双贡双方合计两个大王自动抗贡，由头游领出；未抗贡时大贡方领出。

牌型参考：[JJ 斗地主规则](https://www.jj.cn/news/320/20110920103700018196.shtml)、[黄金岛掼蛋牌型与接风](https://www.80166.com/guide/rule/god.html)。贡还牌和过 A 采用页面明确列出的牌室约定；地方规则存在差异，本应用不标称赛事认证。

## 操作与离线

点击或键盘 Tab + 空格/Enter 选择手牌，然后点击“出牌”。不合法或无法压过桌面的组合无法提交；服务端会再次独立校验。下一副需要每位玩家重新准备，整场结束后房主可重开。

正常结算后，“本副剩余手牌”会自动公开所有未出完玩家的手牌（含昵称、座位与剩余张数）。斗地主整场结束、掼蛋每副结束及过 A 都适用；刷新或结算后离座仍保留亮牌记录，下一副/重开后清除。进行中的手牌始终保密，玩家中途退出导致的提前结束不公开手牌。

- 每轮 60 秒。超时自动不叫或过牌；有领出权时出最小单张；贡还阶段选合法牌。
- 至少一位参与者打开牌桌时，由其请求触发到期操作；服务器检查时间、身份和版本。所有人离线时不在后台继续对局，重新打开后从保存状态恢复。
- 刷新、关页面不清除座位。显式“退出房间”会提前结束正在进行的整场，页面有确认提示。房主离开后由现存玩家接任。7 天未活动的房间不可再进入。
- 一个账号同一时间只能在一个有效房间入座，斗地主与掼蛋共用此限制。等待、对局中及结束后尚未退出的房间都会保留座位；换桌前请点击“退出房间”。同时打开多个标签页也不能重复建房或跨房间入座。观战不占座，关闭或过期房间不再占用名额。
- 当前为真人联机，无人机补位、聊天、观战手牌、积分经济或跨场排行榜。未入座用户只能看到公开牌面。

## 数据与一致性

新增迁移 `drizzle/0001_oval_cardiac.sql` 只增加 `game_rooms` 表及索引，与旧版兼容。房间状态、全部手牌、级别和倒计时存入现有 SQLite/D1；备份现有数据库即包含牌局。图片目录不受影响。

`GET /api/games` 为大厅，`POST /api/games` 建房，`GET /api/games/:id` 读取按账号裁剪的牌局，`POST /api/games/:id` 提交操作。写接口沿用来源检查与 HttpOnly 会话。房间写入使用 `WHERE version=?` 原子比较更新，避免重复出牌或两人抢占一个座位；冲突返回 409 并让客户端重新同步。所有响应 `Cache-Control: no-store`。洗牌使用服务端密码学随机数。对局中的响应字段白名单不包括其他人的手牌；仅正常结算后增加剩余手牌亮牌字段，叫地主结束前不公开底牌。

每个账号每小时最多创建 10 个房间。大厅返回最近 60 个有效房间，用户仍可通过链接进入未过期的老房间。近期牌局记录最多保留 40 条。

跨房间座位检查直接包含在建房 INSERT 和房间 UPDATE 的条件中，使用数据库原子写入保证并发一致性，不依赖大厅最近 60 条记录。重开及其他保留座位的操作也验证同桌玩家，历史重复入座的账号仍可退出多余房间。无需新增表或迁移。

## 验证与本地运行

```sh
npm run test:games
npm run typecheck
NEXT_PUBLIC_BASE_PATH=/melon npm run build:ecs
MELON_DATA_DIR="$PWD/.sites-runtime/card-room-qa" node scripts/init-ecs.mjs
MELON_DATA_DIR="$PWD/.sites-runtime/card-room-qa" MELON_PUBLIC_ORIGIN=http://127.0.0.1:5173 NEXT_PUBLIC_BASE_PATH=/melon npm run start:ecs -- --hostname 127.0.0.1 --port 5173
```

打开 `http://127.0.0.1:5173/melon/games`。

多人接口测试仅允许回环地址与名称包含 `card-room-qa` 的隔离目录，创建的测试账户和房间在结束时清理：

```sh
MELON_DATA_DIR="$PWD/.sites-runtime/card-room-qa" node --experimental-strip-types tests/integration/test-games-api.mts
MELON_DATA_DIR="$PWD/.sites-runtime/card-room-qa" MELON_TEST_URL=http://127.0.0.1:5173/melon npm run test:single-room
MELON_DATA_DIR="$PWD/.sites-runtime/card-room-qa" MELON_TEST_URL=http://127.0.0.1:5173/melon npm run test:ecs
```

原 Vinext 本地模式继续使用 `npm run build`、`npm run db:migrate`、`npm run dev`；路径是 `/games`。ECS 每次启动自动运行新增迁移。回退旧镜像时保留新增表即可，不要删除已有数据库或恢复过时备份覆盖新帖子。

`test:single-room` 使用隔离测试账户验证所有占座阶段、同时建房、同时加入不同房间、建房与加入竞争、同桌换座、退出换桌、关闭/过期房间，以及历史重复座位下的重开和退出。测试房间与账户在结束时清理。Windows PowerShell 请用 `$env:MELON_DATA_DIR` 和 `$env:MELON_TEST_URL` 设置上述环境变量。
