# 注册邮箱验证

新账号填写用户名、固定昵称、密码和邮箱，获取六位验证码后注册，成功后自动登录。验证码十分钟有效、最多输错五次，每次注册都要重新验证。修改用户名或邮箱后需重新获取验证码。失败时保留表单内容。

历史账号继续使用用户名和密码登录，后台显示“历史账号，未绑定邮箱”。本期不提供邮箱登录、密码找回、补绑或换绑。

## 每邮箱十个账号

同一规范化邮箱累计最多注册十个账号；封禁或解封不释放名额。未验证不创建账号，也不占名额。邮箱去除首尾空格并转为小写。

消费者 Gmail 地址额外合并 `gmail.com` / `googlemail.com`、用户名中的点和 `+` 后缀。其他服务商及 Google Workspace 自定义域名不推断别名关系。后台保存输入邮箱及规范化计数键，发信使用规范化地址。

本人登录状态接口与管理员账号接口可读取邮箱；公开个人页、帖子和回复不展示邮箱。管理员“账号”标签可查看验证时间、累计账号数并筛选同邮箱账号。已有封禁及集中注册标记规则不变。

## 接口

以下路径相对于当前部署前缀，支持根路径或 `/melon`。

- `POST /api/auth/email-code`：`{ username, email }`，成功返回 `{ challengeId, expiresIn: 600, retryAfter: 60 }`。
- `POST /api/auth/register`：原注册字段加 `{ email, challengeId, code }`，成功设置 HttpOnly 会话 Cookie。
- `GET /api/auth/me`：本人新增 `email`、`email_verified_at`，旧账号为 `null`。
- `GET /api/admin/users?email=...`：管理员按规范化邮箱筛选，每页二十条。

验证码绑定用途、邮箱和用户名，只有最近一次成功发送的验证码有效。重发失败保留旧码原有效期。消费与账户、会话、名额及 IP 注册标记采用同一事务；重复消费与最后一个名额竞争只能成功一次。所有接口沿用同源验证和 `Cache-Control: no-store`，429 响应包含等待秒数和 `Retry-After`。

## 发信限额

| 范围 | 发送尝试上限 |
| --- | --- |
| 同一规范化邮箱 | 六十秒一次、滚动一小时五次、北京时间每日十次 |
| 同一可信访客 IP | 滚动一小时二十次；未知 IP 不合并统计 |
| 全站 | 北京时间每日二百次 |

额度存入数据库，并发预留不能突破。失败及超时也计数，无自动重试。全站达上限后仍可验证已收到的码、登录历史账号。发信配置缺失或服务异常时禁止免验证注册。

验证码只保存独立密钥的 HMAC 摘要，不保存生产明文。发送尝试和验证请求在发码时清理超过四十八小时的记录；累计名额独立永久保留。开发模式的私有模拟收件箱仅用于回环测试，生产拒绝启用。

迁移 `0004_mature_patch.sql` 兼容旧账号；Node 启动自动迁移，Worker 本地执行 `npm run db:migrate`。详见 [邮件配置和回退](../../deploy/mail/README.md)、[验证记录](../verification/email-registration.md)。
