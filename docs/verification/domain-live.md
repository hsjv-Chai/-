# 根域名与 Cloudflare 接入验证

日期：2026-10-30。本文使用示例地址；真实域名、备案号、账户、证书联系信息、镜像及备份清单保存在私密运行目录，不提交 Git。

## 已完成的接入

- 经站点所有者确认备案成功及阿里云接入后，将应用从 `/melon` 切至根路径。保持 ECS、SQLite、磁盘图片及既有账户数据。
- 根据完整导出复制五条 DNS 记录：根域名 A，以及邮件 SPF、DKIM、DMARC、MX。核对原始内容、MX 优先级和邮件 TTL；仅根域名开启 Cloudflare 代理。
- 核对父区无 DS 后，由站点所有者手动更换 NS。Cloudflare zone 为 active、Free；本轮未开启 DNSSEC，保留原状态。
- 签发可被信任的源站证书，直连与代理/来源限制启用后均通过 Certbot 续期演练，定时器每日两次检查。
- Cloudflare Full (strict)、统一 HTTPS、免费托管防护生效；保留默认脚本加载方式。仅版本化 `/_next/static/` JS/CSS 可缓存，其余路径绕过缓存。
- 来源限制仅作用于论坛域名虚拟主机。原 IP 的 `/melon` 与域名上的旧前缀 GET/HEAD 返回 302 + no-store，保留剩余路径和查询；POST 返回 JSON 410。

## 接入中修复的问题

1. Rulesets API 的 `per_page` 上限为 50。工具改用 50，遇到满页仍拒绝继续，避免未读完整规则时覆盖配置；增加模拟 API 限制及满页拒绝的回归检查。
2. 共用 Docker 网络的两个 Compose 服务都带有 `app` 别名，原站反代可能误入论坛。原站上游固定至其专属容器；原站响应恢复，论坛不再通过该路由绕过来源限制。没有发布原站代码或修改其数据。隔离测试补齐原站专属别名。
3. 同步修正协调回退链中的原站上游；原始配置副本保留用于审计。Nginx 使用原 inode，兼容单文件挂载。

## 验收限制

- 站点所有者指出本机系统代理影响右侧浏览器访问。本轮没有完成生产浏览器、手机或 Safari 的登录、发帖、动画等交互验收。
- 部分 Python HTTP 探针收到 403；标准 curl 请求和 ECS 代理检查通过。保留防护配置，不将结果表述为所有客户端均通过。
- 没有两条真实大陆网络的直连/代理对比数据，不宣称提速、99% 成功率或 P95 性能验收通过。
- 发信 DNS 与运行环境保留；未在本轮重复真实投递验收，也未创建生产测试账户。

## 维护与回退

证书、DNS/缓存规则、私密 readiness 与协调快照的使用见 [接入说明](../../deploy/cloudflare/README.md)。真实备份位置与恢复顺序记录在私密运行目录。

代理异常优先恢复同域名 HTTPS 直连：**先恢复不限制 Cloudflare 来源的 Nginx，再关闭 DNS 代理**。保持根路径、来源、Cookie 和账户数据不变。

需要恢复旧镜像和 `/melon` 时使用对应的协调快照，并为正式域名保留有效证书及维护响应；不以旧数据库覆盖新产生的数据。共享网络的原站上游须保持专属名称，避免再次串站。快照哈希不匹配时先审查后续改动。
