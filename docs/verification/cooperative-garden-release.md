## 回退原则

精确镜像、快照位置和运维命令保存在本地私密运行目录及服务器发布目录，不写入公开仓库。需要回退时：

1. 先核对当前版本和进行中的牌局，备份发布后新增的数据与配置。
2. 短暂阻断 API 写入并再次确认无进行中牌局。
3. 只恢复旧镜像设置，保留现有来源、邮件配置、数据目录和新增合种表；重建应用，检查健康与既有入口。
4. 恢复维护前的 Nginx 内容，保持文件 inode，并检查配置、重载及域名访问。

禁止使用旧数据库覆盖当前数据，也不删除合种迁移或纪念记录。若需要数据结构回退，应另行评审，不能直接倒灌快照。
